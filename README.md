# MenstraCare

MenstraCare is a machine-learning based PCOS (Polycystic Ovary Syndrome)
prediction and model evaluation web application. It serves three pre-trained
scikit-learn pipelines — Logistic Regression, Random Forest, and SVM — behind
a FastAPI backend, and presents a clean, theme-able web UI for running
predictions and reviewing training results.

> **This project uses the existing trained models supplied in
> `MenstraCare.zip`.** No models were retrained, modified, or replaced.
> `MenstraCare_Training.ipynb` was used only to understand the training
> process and to source the real evaluation metrics/visualizations shown on
> the Training Results page.

---

## Features

- **Prediction page** — pick a model (Logistic Regression / Random Forest /
  SVM) from a dropdown, fill in a grouped clinical form, and get a live
  prediction with a probability score.
- **Model selector** — actually switches which trained pipeline the backend
  uses; verified to return different predictions/probabilities per model.
- **Training Results page** — real accuracy / precision / recall / F1 /
  ROC-AUC metrics per model, a metric comparison chart, ROC curves, confusion
  matrices, and Random Forest feature importance — all sourced from the
  training notebook and the trained pipelines, not fabricated.
- **Light / dark theme**, remembered across page navigation.
- **Responsive layout** for desktop, tablet, and mobile.

## Installation

```bash
cd MenstraCare
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## How to run

The FastAPI backend also serves the frontend, so a single command runs the
whole application:

```bash
cd backend
uvicorn app:app --host 0.0.0.0 --port 8000
```

Then open **http://localhost:8000** in a browser.

- Home: `http://localhost:8000/`
- Prediction: `http://localhost:8000/prediction.html`
- Training Results: `http://localhost:8000/training-results.html`
- API docs (auto-generated by FastAPI): `http://localhost:8000/docs`

## Model loading

On startup, `backend/app.py`:

1. Reads `models/deployment_config.json` to find each model's `.joblib`
   filename.
2. Loads all three pipelines with `joblib.load()`.
3. Loads `feature_columns.json`, `feature_info.json`, and `target_info.json`
   to know the exact input schema and class mapping.

Each `.joblib` file is a full `sklearn.pipeline.Pipeline` containing:

- A `ColumnTransformer` preprocessing step (median imputation + `StandardScaler`
  for numeric features; most-frequent imputation + `OneHotEncoder` for any
  categorical features — there are none in this dataset, so all 30 predictors
  are numeric).
- The trained classifier (`LogisticRegression`, `RandomForestClassifier`, or
  `SVC`).

The backend **never** re-implements this preprocessing. It builds a
single-row `pandas.DataFrame` with the 30 raw feature values in the exact
column order from `feature_columns.json`, and calls `pipeline.predict()` /
`pipeline.predict_proba()` directly — the saved pipeline handles imputation,
scaling, and encoding internally, exactly as it did during training.

## How model switching works

`POST /api/predict` takes a `model` key (`logistic_regression`,
`random_forest`, or `svm`) and looks it up in the in-memory dictionary of
already-loaded pipelines. The frontend's model selector on the Prediction
page sends whichever model the user picked, so a different model is
genuinely invoked for each request — this was verified by sending the same
patient input through all three models and confirming different predictions
and probabilities are returned.

## Where the trained models live

`backend/models/*.joblib` — copied unmodified from
`MenstraCare.zip → Training/Models/`.

## How the Training Results page gets its data

`GET /api/training-results` returns:

- **`comparison`** — the exact per-model accuracy / precision / recall / F1 /
  ROC-AUC values from `models/model_performance.json` (produced by the
  notebook's own `calculate_metrics()` step).
- **`confusion_matrices`** and **`roc_curves`** — computed once, offline, by
  loading the same trained `.joblib` pipelines and running them against the
  identical stratified 80/20 test split the notebook used
  (`train_test_split(..., test_size=0.20, random_state=42, stratify=y)` on
  the cleaned `MenstraCare_TrainingData_Modified.xlsx` data). The resulting
  accuracy/ROC-AUC values were checked against `model_performance.json` and
  match exactly, confirming the split and models are faithfully reproduced.
  These are stored in `models/training_artifacts.json` so the backend
  doesn't need the raw training spreadsheet at runtime.
- **`feature_importance`** — the real `feature_importances_` array from the
  trained Random Forest pipeline (top 15 features), matching the values
  produced in the notebook's feature-importance cell.
- **`dataset`** — record counts and train/test split sizes from the cleaned
  dataset (541 records after cleaning: 364 "No PCOS", 177 "PCOS"; 432
  training / 109 test).

Nothing on this page is estimated or invented — every number is either read
directly from a training artifact or recomputed against the same trained
pipeline and verified to match.

## Prediction API

```
POST /api/predict
Content-Type: application/json

{
  "model": "random_forest",
  "features": {
    "Age_yrs": 28, "Weight_Kg": 60, "HeightCm": 156, ...
  }
}
```

Response:

```json
{
  "model": "random_forest",
  "model_label": "Random Forest",
  "prediction": 0,
  "label": "No PCOS",
  "probability": 0.02
}
```

Other endpoints:

- `GET /api/health` — model load status.
- `GET /api/model-info` — model list, feature schema, class mapping (used to
  build the prediction form).
- `GET /api/training-results` — see above.

Invalid model keys and missing features return `400` with a descriptive
`detail` message; unexpected errors return `500`.

## Important notes

- **Dataset scope**: the trained models used all 30 available predictors,
  including hormonal, physical, symptomatic, and ultrasonographic (follicle
  count/size, endometrium thickness) variables. `feature_info.json` reports
  zero categorical features — every predictor was numerically coded in the
  source dataset, including Yes/No symptom fields (0/1). The prediction form
  renders those Yes/No fields as selects for usability while still sending
  0/1 to the API.
- **`scikit-learn` version**: `requirements.txt` pins `scikit-learn==1.6.1`
  to match the version the `.joblib` pipelines were saved with. Loading them
  with a different scikit-learn version can raise an
  `AttributeError` inside `SimpleImputer` during `predict()` — install the
  pinned version to avoid this.
- **Files from the ZIP not used directly by the running app**: the `.git`
  folder and `Training/MenstraCare_TrainingData_Modified.xlsx` were used only
  to verify/reproduce the confusion matrices and ROC curves offline; they are
  not required at runtime and are not bundled into `backend/`.

## Medical disclaimer

MenstraCare's predictions are generated by machine-learning models trained
on a limited dataset, for informational and research purposes only. They are
**not** a medical diagnosis and should not be used to make clinical
decisions. Anyone with health concerns should consult a qualified healthcare
professional.

## Limitations / manual steps

- The backend loads all three models into memory at once; this is fine at
  mini-project scale but would need per-request/lazy loading for a larger
  deployment.
- No authentication, rate limiting, or persistence layer (predictions are
  not logged to a database) is implemented — add these if the project is
  extended beyond a research prototype.
- `CORS` is currently open (`allow_origins=["*"]`) for local development
  convenience; restrict this before any public deployment.
